# Local softmax direction agent with persistent online learning

The change makes a local JSON-persisted BUY/HOLD/SELL softmax classifier the final source of strategic direction, with quality gates, stops, breakers, sizing, reconciliation, and execution checks retained as vetoes. It adds batch training over a five-calendar-year 1h source window, temporal holdout reporting, and optional delayed-label updates with a JSONL experience log. The evaluation boundary, online label timing, durable update protocol, replayability, serving parity, and model promotion behavior have blocking gaps. The generated default model performs below both the majority accuracy baseline and a uniform-probability log-loss baseline.

Watch for: **confirmed** four-hour label overlap across the train/holdout boundary; **confirmed** late online labels using an arbitrary later price; **confirmed** crash-inconsistent model/experience persistence; **confirmed** non-replayable experience records; **confirmed** training/serving feature-formula skew; **confirmed** default promotion of a model that underperforms trivial baselines.

**Verdict**: NEEDS_CHANGES

## High-level view

The temporal split is ordered but not purged. Because each training label reads four future bars, the final four training examples consume prices from the nominal holdout period, so the reported holdout is not strictly isolated (**confirmed**).

Online examples become eligible after four hours, but every eligible item is labeled with the price of whichever qualified runtime evaluation next invokes the model. Outages, quality vetoes, breakers, or scheduling delay therefore change the target horizon from four hours to an unbounded later horizon (**confirmed**).

Resolved examples are appended to the experience file before the updated model and pending queue are atomically replaced. A crash in that interval leaves the old pending item durable while its audit row is already durable, causing duplicate training and logging after restart (**confirmed**).

The resolved experience row omits the feature vector used for training. Once the item leaves `pending`, the online update cannot be reconstructed, replayed, or independently audited (**confirmed**).

Historical proxy construction does not reproduce two serving formulas: runtime tactical confidence includes flow and runtime edge subtracts uncertainty plus spread, while training omits those adjustments. This is avoidable training/serving skew beyond the documented absence of true BBO and aggTrade history (**confirmed**).

The generated artifact scores 0.3803 accuracy versus a 0.4026 majority baseline, and its 1.5525 log loss is worse than the 1.0986 uniform three-class baseline. The trainer still saves it and the CLI loads it as the default directional authority because no quality or promotion gate exists (**confirmed**).

## Four-hour targets cross the temporal holdout boundary

`build_examples` uses the close at `index + 4` as the target (`ml_training.py:168-175`), but `train_from_dataset` splits the already labeled list by example timestamp alone (`ml_training.py:245-247`). The report has adjacent boundaries—training ends at 2025-09-30 09:00 UTC and holdout starts at 10:00 UTC—so the final four training labels consume closes in the holdout feature period (**confirmed**).

Purge training examples whose label-resolution timestamp reaches the holdout start, or split raw rows first and construct each partition with explicit feature and label availability boundaries. Report the purged count and label-end boundary.

## Delayed learning changes horizon after any interruption

`LocalMLAgent.predict` calls `_resolve(snapshot.at, snapshot.price)`, which labels every pending observation older than four hours with that single current price (`local_ml.py:394-403`, `415-425`). There is no price series or lookup for `observed_at + 4h`; an item resolved at 7h receives a 7h return while remaining characterized as a 4h learner (**confirmed**).

Model invocation is bypassed while evidence is unqualified and for breaker/protective exits (`realtime_demo.py:803-829`), making delayed resolution a normal consequence of safety gating. Persist timestamped prices independently of prediction eligibility, resolve against the target within a fixed tolerance, and expire unmatched examples.

## Model checkpoint and experience log can disagree after a crash

Resolution mutates weights and removes pending items, then fsyncs experience rows; only after `_resolve` returns does `predict` save the model (`local_ml.py:395-403`, `425-443`). Failure after the JSONL fsync and before `model.save` restarts from prior weights and queue while retaining the resolved row; the next call retrains and logs it again (**confirmed**).

Use stable update IDs and an idempotent recovery protocol spanning pending, applied updates, and experience records. A local write-ahead journal or SQLite transaction satisfies the no-service constraint.

## Experience records cannot reproduce online updates

`PendingExample` contains raw features, but the resolved row stores only identifiers, timestamps, prices, label, net opportunity, and model version (`local_ml.py:431-446`). The vector disappears when `pending` is replaced with `retained`, preventing replay or independent audit of the SGD input (**confirmed**).

Persist feature schema, exact feature vector, stable update ID, and preferably the pre-update prediction. Test reconstruction from the batch checkpoint plus online experience against the live checkpoint.

## Historical proxies diverge from the serving feature contract

Serving computes tactical confidence as `_confidence(tactical_score + flow * 0.20)` and edge as tactical return minus round-trip cost, uncertainty, and spread (`realtime_demo.py:455-459`). Training emits `_confidence(tactical_score)` and `tactical_return - cost_bps`, despite separately computing a flow proxy and marking spread missing (`ml_training.py:118-138`) (**confirmed**).

The edge feature has non-zero weights in the generated model, so the systematic serving shift can change direction. Centralize derived-feature formulas around common proxy inputs, or omit unavailable fields and retrain; test every unavoidable train/serve substitution.

## An under-baseline artifact is promoted automatically

The report records 0.380335 holdout accuracy against 0.402568 majority accuracy, macro-F1 0.338283, and log loss 1.552465. Uniform three-class probabilities have log loss `ln(3) = 1.098612`, making the model worse than an uninformative probability forecast and the reported majority classifier (**confirmed**).

`train_from_dataset` saves unconditionally (`ml_training.py:293-310`), and `run_realtime_demo.py` defaults to that model as final strategic direction. Require predeclared temporal metrics and calibration checks, encode promotion status in the artifact, and reject unpromoted models at runtime.

## Tests miss the persistence and evaluation boundaries

The online test resolves exactly at `NOW + 4h` and checks only counts (`test_local_ml.py:145-157`). It cannot detect late relabeling, duplicate crash recovery, or missing replay data; the calendar-window test does not verify split purging, and no test gates generated quality or train/serve parity (**confirmed**).

Add tests for late/missing target prices, crash points around both durable writes, replay, purged splitting, formula parity, and rejection of a below-threshold artifact.
